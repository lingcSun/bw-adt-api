# Agent Note: W1/W2/W4 修复（DTP 删除模式、createDTP 预检、parent 校验类型）

Status: implemented

## Problem

写验证轮（[第 8 节笔记](2026-09-21-write-sweep.md)）留下三个可修项：W1 本地 DTP 无法用库删除（transport 模式挡死，服务端其实接受 lock 删除）；W2 createDTP 两个暗坑（TRFN 须 active 才能建、否则报模糊错误 "could not be successfully created"；description 参数被静默丢弃）；W4 通用 createObject 的 parent 校验用对象自身类型（InfoArea 名按 ADSO 查 → 404）。

## Decision

- **W1**：`useLockHandleMode` 纳入 DTP（与 ADSO/InfoArea/TRFN 同列），docstring 同步；`delete({lockHandle})` 参数校验测试翻转。
- **W2**：createDTP 入口加 TRFN 预检——GET TRFN /m，读不到 → 指引 createTransformation；`<objectStatus>inactive` → 明确报"先 saveAndActivateTransformation"。预检只在**能证实 inactive** 时拦截（显式 inactive 标记），避免对未知形态误杀。description 参数保留签名但 JSDoc 标注"不生效"（服务端忽略根元素描述，真实描述为派生字段）。
- **W4**：`BWObject.create` 的 parent 校验类型映射——ADSO → "AREA"（证据支持：专用路径 createADSOFull 即按 AREA 校验成功）；其他类型保持原行为并在注释中提示语义未验证。

## Alternatives considered

- **W2 预检按"非 active 即拦截"**：active 形态未逐字采样（如可能的属性形态），强校验会把未知当失败；改为"证实 inactive 才拦"，未知形态仍交服务端（其报错虽模糊但不阻断）。
- **W2 顺手把 description 写到 overview**：实测 overview@description 是派生字段（PUT 接受不持久），没有可写位置——写文档而非写代码。
- **W4 做成 parentType 通用参数**：除 ADSO 外无任何类型的 parent 语义有证据，通用参数是没被需求支撑的面。

## Consequences

- `deleteObject("dtpa", …)` 的必填参数从 transport 变为 lockHandle（BREAKING，0.x minor 内）；本地 DTP 全生命周期（建/改/激/删）从此在库内闭环。
- createDTP 每次多一个 GET（TRFN 预检）；换来的是失败时一句能照做的报错。
- 依赖"传 description 生效"的调用方（若存在）此前也从未生效过——文档化不改变现状。

## Testing

`w1-w2-w4-fixes.test.ts` + DTP 删除断言翻转共 12 测试绿（拦截/放行/parent 类型路由均 mock 锁定）。真机（库路径）：inactive TRFN 被 W2 明确报错拦截、激活后放行；`obj.delete({lockHandle})` 删除 DTP 回读消失；`createObject("adso", …, {parent: InfoArea})` 成功。写类终态 22 ✅ / 20 ⚠️（范围外登记）/ 1 ❌（W3 executeDTP，待 Eclipse 抓包）。
